# ProtocolAgent — отдельное приложение C#

Консольное приложение .NET 10, без сторонних NuGet-пакетов. Получает локальный
PDF или TXT, извлекает протокол через OpenAI, находит/создаёт соревнование,
разбирает команды и спортсменов и сохраняет результаты через FinCubes API.
В обычном случае промежуточных вопросов нет. При неразличимых кандидатах или
нечитаемом документе задаёт вопрос в консоли. Веб-интерфейса/оконной формы пока нет.

## Настройка

Нужны .NET 10 SDK, работающий FinCubes API с миграцией 18 и доступ к OpenAI API.
Модель задаётся явно: она должна поддерживать PDF/image input, Responses API
и Structured Outputs. Приложение локальное, **распознавание не офлайн**:
документ и необходимые данные кандидатов передаются OpenAI.

PowerShell:

```powershell
$env:FINCUBES_API_URL = 'https://your-api.example/'
$env:FINCUBES_API_TOKEN = '<токен>'
$env:OPENAI_API_KEY = '<ключ>'
$env:OPENAI_MODEL = '<модель с поддержкой PDF и Structured Outputs>'
dotnet run --project tools/ProtocolAgent -- 'C:\Protocols\results.pdf'
```

У токена FinCubes должны быть права `competition:read,create`, `athlete:read`,
`protocol:import` (или соответствующие wildcard-права). URL — корень API,
без `/admin`. HTTP разрешён только на loopback; в остальных случаях HTTPS.
Ключи задаются через окружение, не сохраняются в журнал и не передаются модели.

Дополнительный локальный контекст, например список локаций и пояснения к документу:

```powershell
dotnet run --project tools/ProtocolAgent -- 'C:\Protocols\results.pdf' --context 'C:\Protocols\context.txt'
```

Если соревнование уже точно известно, его можно указать:

```powershell
dotnet run --project tools/ProtocolAgent -- 'C:\Protocols\results.pdf' --competition-id 42
```

Аргументы после `--` передаются приложению. Файл `.json` принимается как готовое
извлечение с корневыми полями `complete`, `issues`, `competition`, `teams`,
`athletes` — это формат `extraction` из журнала, не готовый запрос `prepare`.
Можно использовать его для продолжения после исправления нечитаемых данных.

## Что делает агент

1. Извлекает индивидуальные бассейновые дисциплины подводного спорта:
   APNEA, BIFINS, IMMERSION, SURFACE. Проверяет обязательные данные, время,
   дистанцию, статусы и связи между локальными ключами. Эстафеты пока исключены.
2. Ищет соревнования в окне ±7 дней вокруг извлечённых дат. Точное совпадение
   названия, дат и места использует автоматически; другие варианты сопоставляет
   модель. Если это другое событие — создаёт соревнование. Если даты ошибочны
   настолько, что существующее событие вне окна, требуется исправить источник
   или передать `--competition-id`.
3. Выполняет `prepare`, для неизвестных команд дополняет кандидатов поиском
   справочника и выбирает existing/create. `locations` сохраняет команды и алиасы.
4. Для спортсменов дополняет кандидатов сведениями из базы за соответствующий
   год рождения. Сравнивает имена, учитывая опечатки и инициалы, без фильтра по
   location_id. Модель помогает выбрать между кандидатами.
5. Перед отправкой `finish` повторно ищет кандидатов для предложенных новых
   спортсменов. Сохраняет запрос и отправляет результаты.

## Правило спортсменов: сначала существующий

- Точное совпадение фамилии, имени, года и пола с единственным кандидатом
  привязывается к существующей карточке даже при разных локациях.
- Отсутствующий клуб, город, разные location_id и смена команды не доказывают,
  что человек новый. Карточки в базе не сливаются и не удаляются.
- Если остаются кандидаты без явного противоречия, агент не позволяет модели
  выбрать create. Она должна выбрать существующий ID либо в крайнем случае ask.
- Создание допускается, когда кандидатов нет или все исключены по персональным
  данным: различается известный год/пол/лицензия либо явно несовместимо имя.
  Сравнение имён эвристическое (расстояние редактирования, порог 0.65,
  допускается одна ошибка и совпадающая первая буква для инициалов).
  Лицензии должны быть из одной системы; неизвестные номера не заполняй.
- Несколько неразличимых людей — вопрос пользователю, а не выбор первого ID.
- Повторы участника с одинаковыми именем, фамилией, годом, полом и лицензией
  внутри документа объединяются до prepare, даже при разных командах.
  Исходная команда каждой строки сохраняется в `metadata.source_team`.
  Это выбранная политика приоритета объединения; она не гарантирует различение
  реальных полных тёзок одного года рождения без дополнительных сведений.

Правило реализовано **в C#-агенте**. Прямые вызовы существующего API вне агента
по-прежнему могут явно создать спортсмена: backend в этой задаче не изменён.

## Редкие вопросы

Агент показывает источник, кандидатов и причину. Можно ввести существующий ID.
Для соревнования/команды также доступно `new`; новая команда потребует регион.
Для спортсмена `new` не предлагается, если остались подходящие кандидаты.
Enter завершает работу с сохранением состояния. Это остановка всего текущего
этапа, а не добавление в API третьего варианта решения.

При неполном извлечении агент предлагает путь к исправленному JSON.
Ошибки HTTP/валидации, недостаточные права, конфликт алиасов и недоступность
провайдера завершают запуск с сообщением; автоматическое придумывание исправлений
и бесконечные повторные запросы не выполняются.

## Состояние и повторные запуски

По умолчанию состояние хранится в `%LOCALAPPDATA%\FinCubes\ProtocolAgent`.
Можно задать `PROTOCOL_AGENT_STATE`. Ключ задания — SHA-256 содержимого файла
и URL сервера: одинаковый файл по другому пути продолжает тот же импорт.
Запускай ту же команду после прерывания. Изменённый файл считается новым заданием.

В каталоге задания:

- `state.json`: извлечение, ID соревнования, import_id, принятые решения,
  точные отправляемые запросы, итоговый ответ;
- `decisions.jsonl`: ответы модели и основания выбора.

В журнале есть персональные данные участников; это локальные рабочие файлы.
Принятые решения не спрашиваются заново. Каталог защищён блокировкой от двух
одновременных запусков этого приложения. Блокировка не защищает от другого
компьютера или стороннего импортера.

Запрос создания соревнования не идемпотентен на текущем API. Перед ним
сохраняется отметка, а при перезапуске выполняется повторный поиск. Если исход
запроса неизвестен и точное совпадение не нашлось, повторное создание запрещается:
нужно указать существующий ID после проверки. Для prepare/locations/finish
используется один сохранённый import_id. Изменение URL или файла создаёт новое
задание: глобальная дедупликация разных файлов одного протокола не реализована.

## Сборка и распространение

```powershell
dotnet build tools/ProtocolAgent/ProtocolAgent.csproj -c Release
dotnet publish tools/ProtocolAgent/ProtocolAgent.csproj -c Release -o dist/ProtocolAgent
```

Вторая команда создаёт отдельную папку приложения для запуска при установленном
.NET 10 Runtime. Справка `protocol-import.md` копируется рядом автоматически;
Python для локального агента не нужен, только удалённый API. Исходный проект
использует общую инструкцию из `../../docs/protocol-import.md` при сборке.

Транспорт модели написан по официальной документации
[входных PDF](https://developers.openai.com/api/docs/guides/file-inputs)
и [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).
Успешная сборка не проверяет качество распознавания, полноту извлечения или
совместимость прав/данных конкретного сервера. Эти сценарии требуют реального
протокола и настроенных ключей.
