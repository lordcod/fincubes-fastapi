# Protocol Import v2

Готовая инструкция для ChatGPT: [промпт импорта](protocol-import-prompt.md).

`POST /admin/protocol-import/`, право `protocol:import`.
Обычный сценарий состоит из двух запросов: `prepare` → `finish`.
Между ними можно сделать паузу: черновик хранится в PostgreSQL.
Ни отдельного этапа `locations`, ни вызова `/recent/` больше не нужно.

Перед развёртыванием применить миграцию
`19_20261127120000_protocol_import_v2.py` штатным `aerich upgrade`.
Она копирует город, регион и клуб из текущих локаций в текстовые поля спортсменов
и разрешает черновик без созданного соревнования. Миграция не запускается приложением.
Старый nullable FK сохранён как совместимость хранения, но карточки и импорт
используют текстовые поля; новые записи не привязываются к объектам словаря.
Таблицы объектов и алиасов используются как словарь, существующие правила сохранены.

Это новая версия контракта: `locations` больше не принимается. У результатов
обязательны `key` и `event_key`, у программы — `key`. Старые незавершённые
черновики v1 нельзя продолжать через v2: они возвращают 409. Перед переходом
завершить их старой версией либо подготовить новый импорт v2. Уже записанные
результаты не удаляются. Для старых результатов без категории/этапа потребуется
явное сопоставление через `result_ids`/`relay_ids`.

## Значение разрядов

- `athletes[].license` — текущий разряд из колонки в начале строки протокола.
- `athletes[].results[].final_rank` — разряд из колонки результата, обычно в конце строки.
- `place` — напечатанное место. Оно не пересчитывается.
- `final` — время финала; `final_rank` НЕ является местом в финале и НЕ требует `final`.

Колонки определять по заголовкам, а не только по расположению.
`license` здесь не номер лицензии, дорожки или участника.
Канонические разряды: `IIIЮН`, `IIЮН`, `IЮН`, `III`, `II`, `I`, `КМС`.
Звания: `МС`, `МСМК`, `ЗМС`. Автоматическое обновление не заменяет уже
сохранённые звания. Варианты `1`, `2`, `3`, `1 юн`, `2 юн`, `3 юн` нормализуются.
Различие разрядов не влияет на установление личности.
Ежедневный пересчёт сохраняет текущий разряд при отсутствии подтверждающих
результатов и не понижает его автоматически. Импорт использует наиболее высокий
из текущего разряда, указанного `license` и разрядов в результатах.
Старые числовые значения `final_rank` автоматически не мигрируются: по одному
числу нельзя определить, было ли это местом или разрядом. Их нужно разобрать
по исходным протоколам, если ранее импортировали по старой инструкции.

## 1. Prepare

UUID создать один раз. Повтор с тем же UUID и тем же содержимым возвращает
сохранённое состояние. Другое содержимое с тем же UUID — 409.
`prepare` сохраняет только черновик, без создания спортсменов и результатов.

```json
{
  "type": "prepare",
  "import_id": "0f89f392-fc1a-4ce5-b9f0-d7b6ec35218b",
  "competition_id": 42,
  "mode": "append",
  "teams": [
    {"key": "t1", "alias": "МК СШОР 3", "city": "Казань", "region": null}
  ],
  "distances": [
    {"key": "e1", "order": 1, "stroke": "BIFINS", "distance": 100,
     "relay_count": 1, "gender": "M", "category": "Юноши 14–17 лет",
     "min_year": 2009, "max_year": 2012}
  ],
  "athletes": [
    {"key": "a1", "team_key": "t1", "last_name": "Иванов", "first_name": "Иван",
     "birth_year": 2010, "gender": "M", "license": "II",
     "results": [
       {"key": "p1", "event_key": "e1", "round": "final", "stroke": "BIFINS",
        "distance": 100, "result": "00:48.25", "place": "1", "final_rank": "I",
        "status": "COMPLETED", "metadata": {"source_page": 3}}
     ]}
  ],
  "relays": []
}
```

Вместо `competition_id` можно передать `competition`:

```json
{
  "name": "Первенство",
  "start_date": "2026-11-25",
  "end_date": "2026-11-27",
  "city": "Новосибирск",
  "location": "Бассейн",
  "organizer": "Организатор",
  "course": "LCM"
}
```

Передавать ровно один вариант. Поиск сравнивает нормализованное название,
даты и известные город/длину бассейна. Однозначное совпадение предлагается
автоматически; несколько кандидатов требуют `competition_id` в `finish`.
При отсутствии совпадений соревнование создаётся в `finish`.
Проверка повторяется перед записью.

Ответ `prepare` содержит:

- `competition`: найденный ID, кандидаты, признак планируемого создания;
- `matched`: локальный ключ спортсмена → ID;
- `athletes`: исходные данные, полную карточку автоматического совпадения
  и кандидатов, включая разряд, город, регион и клуб;
- `teams`: исходную подпись, варианты из словаря и выбранные текстовые поля;
- `existing_records`: существующие личные результаты и эстафеты по каждому
  соревнованию-кандидату, включая ID и сохранённые сведения о категории/этапе;
- `replacement`: список ID удаляемых результатов и эстафет, токен подтверждения
  для `replace` при однозначно выбранном соревновании.

Сопоставление учитывает имя, фамилию, год рождения и пол; Е/Ё нормализуются.
Клуб — дополнительный признак сортировки, не условие личности. При нескольких
полных совпадениях выбор остаётся за оператором. Разные исходные ключи нельзя
неявно сопоставить одному спортсмену: объединить выступления человека нужно
при подготовке JSON. Все автоматические совпадения доступны для проверки и замены.

## 2. Finish

```json
{
  "type": "finish",
  "import_id": "0f89f392-fc1a-4ce5-b9f0-d7b6ec35218b",
  "decisions": {"a1": {"action": "existing", "athlete_id": 123}},
  "teams": {"t1": {"club": "СШОР №3", "city": "Казань", "region": "Татарстан"}}
}
```

Для нового спортсмена: `{"action":"create"}`. Автоматические совпадения
можно не дублировать в `decisions`. Неоднозначного участника нельзя создавать
только на основании другого клуба или разряда.
`teams` необязателен: без решения используются поля из `prepare`.
Неизвестная команда сохраняется исходным текстом, неизвестные город/регион — `null`.
`team_key` тоже необязателен; у участника только эстафет `results: []`.
Новые словарные правила не создаются автоматически.

`finish` в одной транзакции создаёт/выбирает соревнование, сохраняет спортсменов,
личные результаты, эстафеты, программу и разряды. Повтор успешного `finish`
с тем же содержимым возвращает сохранённый ответ без повторной записи.
Изменённый запрос после полного завершения — 409.

## Дисциплины и программа

Только бассейновые дисциплины подводного спорта:

| stroke | Дисциплина |
|---|---|
| APNEA | Ныряние в длину в ластах |
| BIFINS | Плавание в классических ластах |
| IMMERSION | Подводное плавание с дыхательным аппаратом |
| SURFACE | Плавание в ластах по поверхности |

Не преобразовывать обычное плавание, фридайвинг или неясные сокращения в эти коды.
`distance` — метры одного этапа, не длина бассейна. `gender`: `M`, `F`,
для смешанной эстафеты — `X`. Исходные заголовки и страницы хранить в `metadata`.

Каждый результат связан с `distances[].key` через `event_key`.
Дисциплина, длина, число этапов, пол, категория и границы годов образуют
идентичность программы. Порядок и локальные ключи не используются для защиты
от дублей. `round` различает выступления в предварительном этапе и финале;
для одного этапа использовать одно стабильное обозначение, например `preliminary`
или `final`. Существующая идентичная дистанция повторно не создаётся.

## Эстафеты

В программу добавить дистанцию с `relay_count > 1`, а в `relays`:

```json
{
  "key": "r1", "event_key": "e2", "round": "final", "name": "СКА 1",
  "stroke": "SURFACE", "distance": 50, "relay_count": 4, "gender": "X",
  "result": "01:21.38", "place": "1", "status": "COMPLETED",
  "legs": [
    {"athlete_key": "a1", "order": 1},
    {"athlete_key": "a2", "order": 2},
    {"athlete_key": "a3", "order": 3},
    {"athlete_key": "a4", "order": 4}
  ]
}
```

Все указанные участники должны присутствовать в `athletes`.
Время этапа необязательно. Если состав отсутствует, передать `legs: []`;
частичный состав разрешён, неизвестных участников не придумывать.
Сохраняется `metadata.protocol_import.composition_complete`.
Номера этапов уникальны, от 1 до `relay_count`; спортсмен не повторяется в составе.
Командное время не превращать в личное время каждого участника.
Изменение состава в режиме `append` возвращает проблему, в `update` обновляет состав.

## Статусы и исходные значения

Поддерживаются `COMPLETED`, `QUALIFIED`, `EXH`, `DNS`, `DNF`, `WDR`, `DSQ`,
для личных результатов также `DSQ_FINAL`.
Время — `mm:ss.SS` или `ss.SS`, ровно две сотых, положительное.
Завершённый результат без времени допустим при наличии напечатанного места.
Причина дисквалификации — `dsq_reason` личного результата;
у эстафеты её можно сохранить в `metadata`.

Для DNS/DNF/WDR/DSQ напечатанные время, место и разряд сохраняются в
`metadata.printed_values`, официальные поля обнуляются.
Для DSQ_FINAL сохраняется предварительное время, а напечатанное время финала
и разряд переносятся в `metadata.printed_final`.
При разных статусах разных этапов предпочтительны отдельные результаты
с разными `round`. Не угадывать неизвестные сокращения: сохранить исходную
строку и уточнить трактовку до отправки.

## Повторный и частичный импорт

`append` по умолчанию добавляет отсутствующие результаты; совпавшие оставляет
без изменений, отличающиеся возвращает как проблемы.
`update` обновляет однозначно сопоставленные выступления.
Сравнение включает соревнование, спортсмена/команду, дисциплину программы
и этап. Новый UUID сам по себе не создаёт дубликат уже известного выступления.
Старые записи без идентичности программы не сопоставляются по одному времени:
выбрать ID из `existing_records`, передать `result_ids: {"p1": 456}` или
`relay_ids: {"r1": 789}`. ID проверяется на принадлежность соревнованию,
спортсмену/команде и дисциплине.

`replace` заменяет все личные результаты и эстафеты выбранного соревнования,
но не удаляет спортсменов и программу. В `finish` нужен `replace_token` из
предварительного ответа. Если данные изменились, сервер возвращает новый план
без удаления результатов. При неоднозначном выборе соревнования план может
потребовать дополнительного обмена. Частичная замена запрещена: ошибка
откатывает всю транзакцию. В `replace` не передавать `result_ids`/`relay_ids`.

Для спортсменов (`decisions`), результатов (`results`) и эстафет (`relays`)
можно передать `{"action":"skip","reason":"..."}` либо
`{"action":"defer","reason":"..."}`. Эти записи остаются в `omitted`.
Зависимые от неразрешённого участника записи остаются в `issues`.

При незавершённых или пропущенных записях ответ `type: partial`, отметка полной
обработки не обновляется. Исправленные решения можно отправить повторным
`finish`; сохранённые результаты не записываются повторно. Решения о пропуске
сохраняются между запросами. Для возврата отдельного результата/эстафеты в работу
передать его ключ в `resume`; для спортсмена — новое решение `existing`/`create`.
Уже записанные сопоставления спортсменов и текстовые поля команд в этом
черновике менять нельзя; для исправления нужен новый импорт `update`.

`GET /admin/protocol-import/{import_id}/` возвращает стадию и последний ответ.
Повтор `prepare` с исходным содержимым тоже возвращает состояние.

Итог содержит количества созданных/обновлённых/совпавших результатов и эстафет,
созданных спортсменов и дистанций, обновлённых разрядов; `results_processed`,
`results_total`, `relays_processed`, `relays_total`, сопоставления, `issues`,
`omitted`, `last_processed_at_updated`. Только полный импорт возвращает
`finished` и обновляет `Competition.last_processed_at`.

## Словарь команд и карточки спортсменов

У спортсмена `club`, `city`, `region` — самостоятельные необязательные строки.
Импорт сохраняет исходную подпись и выбранную расшифровку вместе с результатом
в `metadata.protocol_import.team`. Обновление словаря и переход спортсмена
не переписывают эти исторические сведения. Импорт не меняет текущий клуб
существующего спортсмена по старому протоколу; карточка редактируется отдельно.

`/admin/team-dictionary/`:

- GET — список правил, необязательный `query`;
- POST — новая запись, право `athlete:create`;
- PUT `/{id}/` — заменить поля и полный список алиасов, право `athlete:write`;
- DELETE `/{id}/` — убрать активные алиасы, право `athlete:write`.

```json
{
  "aliases": ["СШОР №3", "МК СШОР 3", "СШОР-3 г. Казань"],
  "club": "СШОР №3", "city": "Казань", "region": "Татарстан",
  "required": ["city"]
}
```

`required` содержит `city` и/или `region`: без соответствующего контекста правило
не применяется автоматически. При нескольких возможных расшифровках они
возвращаются кандидатами. Без словаря импорт тоже работает. Неизвестные поля
можно передавать `null`. Удаление правил не удаляет карточки и результаты.
Старые API словаря остаются доступны для совместимости, но больше не являются
обязательным этапом импорта. Старый `location_object_id` в запросе редактирования
спортсмена служит лишь источником копирования строк и не закрепляет связь.
