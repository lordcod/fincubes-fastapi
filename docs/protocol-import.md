# Импорт протокола для ИИ

Один endpoint: `POST /admin/protocol-import/`. Право доступа: `protocol:import`.
Три запроса: `prepare` → `locations` → `finish`. Решение для команды или
спортсмена имеет только два вида: `existing` (ID) либо `create`.

Перед первым использованием применить миграцию `18_20261125120000_protocol_import.py`
обычным для проекта способом (`aerich upgrade`). Миграция создаёт таблицу черновиков.
Она не изменяет существующие локации, спортсменов и результаты.

## Область обработки: только подводный спорт

Обрабатывай индивидуальные бассейновые дисциплины подводного спорта из таблицы
ниже. Обычное спортивное плавание (вольный стиль, брасс, спина, баттерфляй,
комплекс) в этот импорт не входит. Не преобразовывай вольный стиль в SURFACE,
а брасс или кроль — в BIFINS. Не включай фридайвинг, ориентирование,
дайвинг и другие дисциплины, для которых здесь нет отдельного обозначения.

Если документ смешанный, извлекай только подходящие дисциплины и сообщи
в сопроводительном ответе, какие разделы не включены. Не называй такой импорт
полной обработкой всех результатов документа. Эстафеты этим endpoint пока
не поддерживаются: не превращай командное время в личные результаты участников.

### Значения stroke

В JSON используй строго эти значения, заглавными латинскими буквами:

| `stroke` | Дисциплина | Обозначения в протоколе при соответствующем контексте | Дистанции в текущем справочнике проекта, м |
|---|---|---|---|
| `APNEA` | Ныряние в длину в ластах | AP, apnea, ныряние | 50 |
| `BIFINS` | Плавание в классических ластах | BF, bifins, классические ласты, КЛ | 50, 100, 200, 400 |
| `IMMERSION` | Подводное плавание с дыхательным аппаратом | IM, immersion, подводное плавание | 100, 400 |
| `SURFACE` | Плавание в ластах по поверхности | SF, surface, плавание в ластах, ПЛ | 50, 100, 200, 400, 800, 1500 |

Коды и перечень дистанций взяты из `app/shared/utils/metadata.py` (`swim_styles`).
Это справочник проекта, не полный перечень дисциплин всех регламентов.
API ограничивает четыре значения `stroke`, но принимает любое положительное
целое `distance`. Если в протоколе другая дистанция той же дисциплины,
сохраняй её фактическое значение, не заменяй ближайшей из таблицы.

Сокращения расшифровывай по заголовку дисциплины, легенде и контексту документа.
Одно слово «ласты» или число метров не позволяет автоматически отличить
SURFACE от BIFINS. IM в протоколе обычного плавания не является основанием
выбрать IMMERSION. Не определяй стиль по скорости спортсмена.
Неясное название необходимо уточнить до формирования запроса, а исходный
заголовок сохранить в `metadata.discipline_raw`.

`distance` — целое число метров, например `100`, без единиц измерения.
Длина бассейна 25/50 м не является дистанцией заплыва; соревнование выбирается
через `competition_id`. Не объединяй разные соревнования одним запросом.

## 1. Извлечь документ и отправить prepare

Создай UUID `import_id` один раз на импорт и сохраняй его для всех повторных запросов.
Соревнование должно уже существовать. Каждой команде и участнику назначь локальный
ключ. Несколько результатов одного человека помести в его `results`.
Одинаковые ФИО и год сами по себе не разрешают объединять разных участников документа.

```json
{
  "type": "prepare",
  "import_id": "0f89f392-fc1a-4ce5-b9f0-d7b6ec35218b",
  "competition_id": 42,
  "teams": [
    {"key": "t1", "alias": "МК СШОР 3", "city": "Казань", "region": null}
  ],
  "athletes": [
    {
      "key": "a1", "team_key": "t1",
      "last_name": "Иванов", "first_name": "Иван",
      "birth_year": 2010, "gender": "M",
      "results": [
        {
          "stroke": "SURFACE", "distance": 100,
          "result": "01:02.34", "place": "1", "status": "COMPLETED",
          "metadata": {"source_page": 3, "source_text": "Исходная строка"}
        }
      ]
    }
  ]
}
```

`stroke`: только `APNEA`, `BIFINS`, `IMMERSION`, `SURFACE` по таблице выше.
Другие значения отклоняются API с 422. `gender`: `M` — мужчины/юноши/мальчики,
`F` — женщины/юниорки/девочки; пол берётся из строки или заголовка раздела,
не угадывается по имени.
Пока поддерживаются индивидуальные результаты и текущая модель имени/года рождения.
Полная дата рождения, отчество и эстафеты не добавляются этим endpoint.

### Как извлекать участников и команды

- `last_name` — фамилия, `first_name` — имя. Не дописывай отчество к имени:
  это изменит сопоставление с существующими карточками. Полное исходное ФИО
  можно сохранить в `metadata.athlete_name_raw` каждого результата.
- Если указана полная дата рождения, передай её год в `birth_year`, а исходную
  дату сохрани в `metadata.birth_date_raw`. Не восстанавливай год по возрастной
  категории и не выдумывай день/месяц.
- `license` — только явно указанный идентификатор лицензии. Номер дорожки,
  стартовый номер или место не являются лицензией.
- `teams[].alias` — принадлежность ровно как в протоколе. `city` и `region`
  заполняй по явным сведениям документа или предоставленного пользователем
  справочника. Город проведения соревнования не означает город всех участников.
- Предоставленный пользователем справочник используй для уточнения контекста.
  В `prepare` всё равно передаются локальные `key` и исходный `alias`;
  выбор реального `location_id` выполняется на этапе `locations`.
- Одинаковое название команды в разных явно указанных городах должно иметь
  разные `team_key`. Одну и ту же команду в одинаковом контексте не дублируй
  для каждого заплыва.
- Тренера не подставляй вместо клуба. Если это единственная подпись принадлежности,
  сохрани её исходной строкой в `alias`, а уточнение — в metadata результата;
  не придумывай по ней школу, город или регион.
- В `metadata` сохраняй страницу, исходную строку, заголовок дисциплины,
  возрастную категорию и этап, если они указаны. Эти сведения помогают
  отличать результаты и проверять извлечение; произвольные поля верхнего уровня
  API не принимает.

### Этапы, места и статусы

Не путай стартовый протокол с итоговым: заявочное время, личный рекорд,
промежуточная отсечка и время победителя из заголовка не являются результатом
этого участника. Не импортируй строку заявки как завершённое выступление.

`place` — итоговое место в соответствующем зачёте предварительного/единственного
этапа, `final_rank` — место в финале. Номер дорожки и номер заплыва сохраняются
при необходимости в metadata. Не вычисляй место сортировкой времён:
возможны разные категории, равные места и внеконкурсные выступления.

Если предварительный этап и финал однозначно относятся к одному участнику,
дисциплине и зачёту, используй одну запись с `result`/`place` и `final`/`final_rank`.
Если опубликован только явно обозначенный финал, заполняй `final`/`final_rank`,
а `result`/`place` оставляй пустыми. Для единственного этапа используй `result`/`place`.
Не склеивай разные категории или несколько финалов; сохраняй их отдельными
записями с пояснением в metadata. Статус здесь общий для записи:
сложные сочетания статусов разных этапов нельзя терять при объединении.

| `status` | Когда использовать |
|---|---|
| `COMPLETED` | Обычный завершённый результат |
| `QUALIFIED` | В протоколе явно отмечен выход в следующий этап, например Q/q по легенде |
| `EXH` | Явно указано выступление вне конкурса |
| `DNS` | Не стартовал / неявка |
| `DNF` | Стартовал, но не закончил дистанцию |
| `WDR` | Явно указан отказ/снятие с участия, а не дисквалификация |
| `DSQ` | Дисквалификация |
| `DSQ_FINAL` | Дисквалификация в финале при сохранении отдельного предварительного результата |

Русские сокращения трактуй по легенде документа. Не заменяй непонятный статус
на COMPLETED. `points` и `record` копируй только из соответствующих колонок:
очки не равны месту, спортивный разряд не равен рекорду.

Время: `mm:ss.SS` или `ss.SS`, ровно две цифры сотых, положительное,
минуты и секунды от 0 до 59. Допустима запятая. Финальное время — `final`,
место в финале — `final_rank`. Места передаются строками.
Для DNS/DNF/WDR/DSQ официальные времена и места должны быть `null` или отсутствовать;
напечатанные при этих статусах значения сохраняй в `metadata`.
Для DSQ_FINAL нет официального финального времени и места, предварительный результат допустим.
COMPLETED/QUALIFIED/EXH требуют времени. Не придумывай отсутствующие сведения.

Ответ:

```json
{
  "type": "locations",
  "import_id": "0f89f392-fc1a-4ce5-b9f0-d7b6ec35218b",
  "matched": {},
  "choices": [
    {"key": "t1", "source": {"key": "t1", "alias": "МК СШОР 3", "city": "Казань", "region": null}, "candidates": []}
  ]
}
```

`matched` содержит автоматически найденные ID. `choices` — команды, для которых
нужно передать ID либо создать новую. Сервер сам читает справочник, включая алиасы.
Возвращаются все точные кандидаты и до десяти похожих. Похожесть — подсказка,
не доказательство совпадения. При необходимости используй существующий поиск
`GET /admin/locations/aliases/` сообразно его параметрам.

## 2. Отправить locations

Для всех ключей из `choices` передай решение. Ключи из `matched` можно не повторять
или явно переопределить. Если всё найдено, отправь пустой объект `decisions`.

Выбрать существующую:

```json
{
  "type": "locations",
  "import_id": "0f89f392-fc1a-4ce5-b9f0-d7b6ec35218b",
  "decisions": {
    "t1": {"action": "existing", "location_id": "27a33201-fd5d-4802-8491-76079239f7a2", "required": ["city"]}
  }
}
```

Либо создать новую — вместо значения `t1`:

```json
{
  "action": "create",
  "location": {
    "club": "МКСШОР № 3", "city": "Казань", "region": "Республика Татарстан",
    "aliases": ["МКСШОР № 3"], "required": ["city"]
  }
}
```

На этом этапе сервер **сохраняет команды и алиасы** в одной транзакции.
Исходное написание добавляется в алиасы автоматически. Отдельно обновлять
справочник не требуется. Правила конфликтов существующего справочника сохраняются.
`required` задаёт необходимый контекст для будущего распознавания алиаса.
Для новой локации регион обязателен по текущей модели.

Ответ имеет `type: "finish"`, `matched` с ID спортсменов и `choices` с кандидатами.
Однозначное совпадение имени, фамилии, года, пола и location_id без конфликта
лицензии попадает в `matched`. Несколько совпадений — в `choices`.
Кандидаты также включают совпадающие имена с другими локациями и похожие имена
того же года рождения и пола. Для поиска вне этого набора используй существующий
`GET /admin/athlete/`. Совпадение команды само по себе не подтверждает человека.

## 3. Отправить finish

```json
{
  "type": "finish",
  "import_id": "0f89f392-fc1a-4ce5-b9f0-d7b6ec35218b",
  "decisions": {
    "a1": {"action": "existing", "athlete_id": 123}
  }
}
```

Для нового спортсмена: `"a1": {"action": "create"}`. Данные берутся из `prepare`,
локация — из второго этапа. Для автоматически найденных достаточно не передавать
решение; его также можно переопределить. Отсутствие кандидатов не создаёт человека
автоматически: передай `create`. Выбранный существующий спортсмен не меняет свою
текущую локацию. Принадлежность из протокола сохраняется в metadata результата.

Сервер атомарно создаёт новых спортсменов и все результаты. Ответ:

```json
{
  "type": "finished",
  "import_id": "0f89f392-fc1a-4ce5-b9f0-d7b6ec35218b",
  "athletes": {"a1": 123},
  "created_athlete_ids": [],
  "results_created": 1
}
```

## Повторные запросы и ошибки

- Повтор идентичного `prepare` возвращает текущий ответ импорта.
- Повтор идентичного `locations` или `finish` возвращает сохранённый ответ этапа.
- Изменение уже принятого запроса с тем же ID даёт 409. Для исправленного
  исходного JSON нужен новый импорт; не повторяй уже сохранённые результаты.
- Ошибки структуры, времени и статуса дают 422 до создания черновика.
- Отсутствующее решение или неизвестный ключ решения дают 422.
- Несуществующий выбранный ID даёт 404; конфликт алиаса — 409.
- Ошибка этапа откатывает записи этого этапа целиком.
- Защита от повторов действует в пределах `import_id`. Новый UUID для того же
  протокола считается новым импортом и может создать дубли.

Никаких решений `skip`, `unknown`, `later` в API нет. Отсутствующие сведения
нельзя выдумывать: если нельзя обоснованно выбрать ID или заполнить новую запись,
запрос этого этапа пока невозможно составить корректно.

## Короткая инструкция для ИИ

Обрабатывай только подводный спорт: APNEA (ныряние), BIFINS (классические ласты),
IMMERSION (подводное плавание с аппаратом), SURFACE (ласты по поверхности).
Не включай обычное спортивное плавание и эстафеты в этот endpoint.
Извлеки протокол по схеме `PrepareImport` и правилам этого документа,
сохрани исходные строки и заголовки в metadata. Используй значения stroke
строго из таблицы. Сверь страницы и дисциплины, чтобы не потерять строки;
нечитаемые значения не восстанавливай догадками. Выводи JSON без комментариев
внутри JSON; сведения о не включённых разделах сообщай отдельно.
Выполни prepare. По choices команд передай locations: для каждой existing с ID
или create с данными локации. Затем по choices спортсменов передай finish:
existing с ID либо create. Найденные matched повторять не нужно.
Используй только реальные ID из ответов API/поиска. Не создавай человека только
из-за другого написания команды. Не выбирай между однофамильцами по порядку
кандидатов или одной лишь похожести. Сохраняй import_id для безопасных повторов.
